# Human Escalation Policy

## Purpose

The customer-support agent should escalate requests when an action cannot be performed safely,
when information is insufficient, or when human judgment or authorization is required.

## Mandatory Escalation Cases

The following requests must be escalated:

- refund authorization
- duplicate payment charges
- warranty approval or denial
- damaged-item compensation
- replacement authorization
- shipping address changes
- suspected fraud
- requests involving account ownership disputes
- inconsistent or unavailable order data
- shipping delays that meet the escalation threshold
- exceptions to published policies

## Shipping Escalation

A shipping issue should be escalated to the logistics team when:

- tracking has shown no movement for more than 5 business days, or
- the package has not arrived within 3 business days after the promised delivery window

The support agent must not promise a refund or replacement before logistics review.

## Clarification Before Escalation

If a request is safe but missing required information, the support agent should first ask for
clarification.

Examples:

- missing order number
- missing customer email
- unclear product name
- unclear request

## Immediate Escalation

The agent should escalate immediately when the requested action involves financial,
authorization, identity, or irreversible consequences.

## Escalation Record

An escalation should include:

- reason for escalation
- customer message
- order number, if available
- relevant retrieved policy
- agent action taken before escalation

The agent must not claim that an escalated request has been approved. It should only state
that the case has been submitted for human review.
